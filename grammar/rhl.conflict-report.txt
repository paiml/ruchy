WHY THE CONTROL IS DISCRIMINATING, AND NOT JUST "SOMETHING WENT WRONG"
    LALRPOP's Err value renders as the generic string "invalid data" for a
    conflict and for a mere typo alike — measured, 2026-09-20. Matching on that
    message would let a renamed or corrupted fixture pass the positive control
    for the wrong reason. So the gate runs a three-way DIFFERENTIAL instead:

        grammar/rhl.lalrpop                       -> Ok
        grammar/fixtures/ambiguous.lalrpop        -> Err
        the same fixture, with the single planted
        production deleted and nothing else       -> Ok

    The third run is built at test time by deleting the one line the fixture
    marks "UNMARKED attribute block — the planted defect". Because that line is
    the only difference between a grammar LALRPOP accepts and one it rejects,
    the rejection is attributable to the planted ambiguity and to nothing else.
    A typo, a missing file, or a bad edit fails the third run too, and the gate
    goes RED rather than quietly passing.
